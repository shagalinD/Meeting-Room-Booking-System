# Meeting Room Booking System

Система для бронирования переговорных комнат с чистой архитектурой, кэшированием и авторизацией.

## 📋 Описание

Проект представляет собой **бэкенд-сервис** для управления бронированиями переговорных комнат. Разработан с использованием современных подходов и лучших практик Go.

### Ключевые особенности

*   **Чистая архитектура** — строгое разделение на слои Handler → Service → Repository.
*   **Генерация кода** — использование `sqlc` для типобезопасных запросов к БД.
*   **Кэширование** — гибридный подход с Redis (внедрение в процессе).
*   **Конфигурирование** — управление через переменные окружения.
*   **Контейнеризация** — полная настройка через Docker Compose.

## 🚀 Быстрый старт

### Локальный запуск

```bash
# 1. Клонируйте репозиторий
git clone https://github.com/shagalinD/Meeting-Room-Booking-System.git
cd Meeting-Room-Booking-System

# 2. Соберите и запустите контейнеры
docker-compose up -d

# 3. Примените миграции (или используйте механизм в коде)
make migrate-up

# 4. Запустите приложение (или используйте Makefile)
go run cmd/api/main.go
```

Приложение будет доступно по адресу: `http://localhost:8080`.

### Использование Makefile

```bash
make help         # Показать все доступные команды
make build        # Собрать бинарный файл
make run          # Запустить приложение
make test         # Запустить тесты
make migrate-up   # Применить миграции БД
make migrate-down # Откатить миграции
```

## 🏗 Архитектура и структура проекта

Проект организован вокруг принципов **чистой архитектуры** и **предметно-ориентированного проектирования (DDD)**.

```
.
├── cmd/
│   └── api/                 # Точка входа в приложение
│       └── main.go          # DI контейнер, инициализация и запуск
│
├── internal/                # Внутренний код, закрытый для импорта
│   ├── domain/              # Сущности и интерфейсы бизнес-логики (ядро)
│   │   ├── auth.go
│   │   └── booking.go
│   │
│   ├── repository/          # Реализация паттерна Репозиторий
│   │   ├── postgres/        # Реализация на базе PostgreSQL (sqlc)
│   │   │   ├── db/          # Сгенерированный код sqlc
│   │   │   ├── auth.go
│   │   │   └── booking.go
│   │   └── cache/           # Кэширующий декоратор (Redis)
│   │       └── booking.go
│   │
│   ├── service/             # Слой бизнес-логики (Use Cases)
│   │   ├── auth.go
│   │   └── booking.go
│   │
│   └── handler/             # HTTP-обработчики (транспортный слой)
│       ├── auth.go
│       └── booking.go
│
├── migrations/              # SQL-миграции БД (goose)
│
├── pkg/                     # Публичные пакеты, переиспользуемые компоненты
│   ├── config/              # Загрузка конфигурации
│   ├── errors/              # Кастомные ошибки
│   ├── logger/              # Инициализация и настройка логгера
│   └── security/            # JWT, хеширование паролей и другие утилиты
│
├── queries/                 # SQL-запросы для генерации кода sqlc
│
├── docker-compose.yaml      # Запуск всех зависимостей (PostgreSQL, Redis)
├── Makefile                 # Автоматизация задач
├── sqlc.yaml                # Конфигурация генерации кода
└── go.mod                   # Модуль и зависимости
```

### Взаимодействие слоев
В `cmd/api/main.go` происходит **внедрение зависимостей (Dependency Injection)**:
1.  Инициализируются подключения к PostgreSQL и Redis.
2.  Создается слой `repository` (например, на основе `sqlc.Queries`).
3.  Если нужен кэш, репозиторий оборачивается в `cache`-декоратор.
4.  Репозиторий внедряется в `service`.
5.  `service` внедряется в `handler`.
6.  `handler` регистрируется в роутере.

## 💡 Ключевые архитектурные решения

*   **Интерфейсы на уровне Domain**: Сервисы зависят от интерфейсов, а не от конкретных реализаций. Это позволяет легко подменять и тестировать компоненты.
*   **Кэш как декоратор**: Кэширование реализовано через паттерн декоратор, который прозрачно оборачивает основной репозиторий. Это сохраняет бизнес-логику "чистой" и позволяет включать/отключать кэш без изменения кода сервисов.
*   **Генерация кода**: `sqlc` генерирует типобезопасный и эффективный код для работы с БД, что снижает количество ошибок и ускоряет разработку.
*   **Структурированное логирование**: Используется пакет `log/slog` для структурированных логов, что упрощает их анализ.
